Architecture Decision Records (ADRs)
Decision Pain Point Implementation Strategy Trade-off Accepted
Request-Level Caching
Used short-lived node-local response caching instead of distributed caching for repeated read requests.		 Repeated identical requests created unnecessary downstream load and increased susceptibility to request bursts and lightweight DDoS-style traffic amplification. Implemented short-lived in-memory response caching with tenant-aware cache partitioning and selective invalidation on POST/PUT/DELETE operations to reduce repeated downstream processing. Accepted temporary stale responses for up to 30–60 seconds in exchange for significantly reduced downstream traffic and improved gateway stability.
In-Memory Configuration State
Maintained local in-memory copies of routing and system configuration instead of performing runtime configuration lookups.		 Runtime configuration lookups introduced unnecessary latency and created operational dependency on centralized configuration services during request processing. Gateway nodes preload YARP routes and system configuration into memory during startup and periodically refresh state through scheduled reloads and event-driven notifications from the configuration server. Accepted temporary configuration drift between nodes in exchange for lower request latency, reduced configuration server load, and improved runtime resilience.
Distributed Identity
Adopted distributed JWT-based identity propagation using Keycloak instead of centralized server-side sessions.		 Requests traversed multiple services and async boundaries, making sticky-session authentication unreliable and difficult to scale horizontally. Built a centralized ASP.NET gateway pipeline using JwtBearer middleware and YARP to validate JWT claims, propagate tenant context, and enforce cross-service authorization policies. Accepted increased complexity in token lifecycle management, including token expiration, revocation strategy, and distributed policy synchronization.
Gateway Resilience Policies
Applied gateway-level retry and circuit breaker policies using Polly for downstream service communication.		 Transient downstream failures and timeout amplification risked cascading outages across dependent services during traffic spikes. Implemented centralized resilience policies for YARP outbound proxy communication by integrating Polly into the underlying HTTP client pipeline. Retry policies were selectively applied only to idempotent operations and transient failure scenarios to avoid duplicate side effects during downstream recovery attempts. Accepted temporary request rejection and increased retry latency in exchange for preventing cascading failures and improving overall system stability.
